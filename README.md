# Персональный новостной агрегатор

Читает 37 источников напрямую (RSS, Google News, веб-версии телеграм-каналов),
склеивает сообщения об одном событии в одно, оценивает важность и публикует
в три личных телеграм-канала. Второй телеграм-аккаунт не нужен.

- **A — Главное**: политика и экономика. Дайджесты 08:00 / 14:30 / 20:00, срочное — сразу.
- **B — Город**: Москва и Краснодар, только то, что меняет планы. 09:00 / 19:30.
- **C — Разбор**: наука, история, деньги, технологии. 18:30 + французский пост в 08:30.

С 23:00 до 07:30 не приходит ничего: срочное копится и выходит утром.

## Как это устроено

```
источники ──► сбор ──► rule-фильтр ──► кластеризация ──► скоринг ──► публикация
  RSS          10 мин    шум, гео,       simhash +        формула +    дайджест
  Google News  20 мин    содержательность сущности +      LLM для       или
  t.me/s/       5 мин                     LLM для спорных верхушки    срочное
```

| Файл | За что отвечает |
|---|---|
| `sources.yaml` | каталог источников: тип, канал, вес, гео |
| `config.yaml` | пороги, расписание, лимиты, фильтры, бюджет на модель |
| `news/collect/` | четыре способа сбора, каждый изолирован от остальных |
| `news/dedup.py` | склейка одного события из разных источников |
| `news/score.py` | базовая формула + уточнение моделью |
| `news/publish.py` | форматирование, две полосы, лимиты, тихие часы |
| `news/french.py` | ежедневный французский пост |
| `news/commands.py` | команды бота и обратная связь 👍/👎 |
| `news/pipeline.py` | один тик: собрать → склеить → оценить → опубликовать |

Конвейер устойчив к падениям: сломавшийся источник помечается и пропускается,
недоступная модель отключает только уточнение — публикация продолжается
на правилах, а не останавливается.

## Запуск

Прод — GitHub Actions по расписанию (`.github/workflows/pipeline.yml`), каждые 10 минут.
Настройка с нуля описана в [SETUP.md](SETUP.md).

Локально:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # заполнить токены
.venv/bin/python -m news.cli check-sources
.venv/bin/python -m news.cli tick
```

Без `DATABASE_URL` используется SQLite в `data/news.db`, без ключа модели
конвейер работает на правилах, `DRY_RUN=1` печатает посты в консоль вместо телеграма.

### Команды CLI

```
tick            полный цикл (то, что запускает планировщик)
collect         только сбор
dedup / score   только склейка / только оценка
digest --channel A|B|C     собрать и выпустить дайджест
urgent          проверить экстренную полосу
french          французский пост
check-sources   отчёт по живости источников
weekly / filter-report     недельный обзор / отчёт по фильтрации
stats           что происходило за сутки
```

### Команды в телеграме

`/digest`, `/queue`, `/focus`, `/quiet`, `/exam_mode`, `/sources`, `/add`,
`/mute`, `/check_sources`, `/stats` — подробности по `/help`.

## Проверка

```bash
.venv/bin/python scripts/selftest.py
```

47 проверок на синтетических данных: фильтры, склейка событий, скоринг,
лимиты, тихие часы, команды, французский пост. Сеть и токены не нужны.

## Стоимость

По умолчанию используется Groq (бесплатный тариф, `openai/gpt-oss-120b`).
Модель вызывается только по делу: спорные пары при склейке, оценка верхушки
батчем, пересказ того, что реально публикуется. Число запросов за прогон
ограничено квотами `llm.quotas`, а под лимит 8000 токенов в минуту включается
компактный режим (`llm.compact`): меньше батчи, короче тексты.

С `LLM_PROVIDER=anthropic` работают Haiku для оценки и Sonnet для пересказов,
с дневным потолком расхода `llm.daily_budget_usd`. При исчерпании лимита,
ошибке провайдера или отсутствии ключа конвейер продолжает работать на правилах.

GitHub Actions для публичного репозитория бесплатен, Neon и Telegram — тоже.
